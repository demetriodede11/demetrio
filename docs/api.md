# Настройка API

[К основной документации](../README.md)

## Подключение

Браузер обращается к `/api/backend/*` на домене приложения. Обработчик Next.js
передаёт запросы на `API_BASE_URL/bxapi/v1/*` и адаптирует куки к новому домену.

Серверные компоненты импортируют `serverApiClient` из `$shared/api/server`.
Он выполняет GET напрямую к тому же backend с таймаутом 10 секунд, передаёт
сессионные cookies и служебные заголовки, запрещает перенаправления.
Изменения данных выполняются браузером через прокси. Серверные модули защищены
встроенным импортом Next.js `server-only`; отдельный npm-пакет не установлен.

Задайте переменные окружения при запуске сервера:

- `APP_ORIGIN` — публичный адрес приложения, например `https://example.com`, без пути,
  логина и пароля. Обязателен в production; локально можно опустить — используется
  адрес запроса. В Docker/VPS указывайте внешний HTTPS-адрес, а не адрес контейнера.
- `API_BASE_URL` — адрес сервера API: `https://<домен>`, без пути, логина и пароля.
  Для каждого окружения используется свой адрес.
- `API_UPSTREAM_AUTHORIZATION` — необязательный заголовок авторизации сервера API.
  Если требуется Basic Auth, секрет внедряется из Vault и остаётся на сервере.
- `API_SESSION_COOKIE_NAME` — имя сессионной куки, по умолчанию `PHPSESSID`.
  Куки с префиксом `BITRIX_SM_` также передаются.

## Сессия и ограничения

Куки получают домен приложения и `Path=/`; флаги `Secure`, `HttpOnly`, `SameSite`
сохраняются. Вход на другом сайте автоматически не переносится. Проверяйте
авторизацию через HTTPS.

Авторизация использует сессионные cookies. CSRF-токен не сохраняется и не добавляется
в запросы: текущие контроллеры backend его не проверяют. Защита POST на прокси
основана на строгой проверке `Origin`.

Таймаут сервера API — 10 секунд, Axios — 15 секунд. Тело POST ограничено 2 МБ.
Прокси не кэширует ответы и не следует перенаправлениям. Для POST проверяется
`Origin`: он должен совпадать с `APP_ORIGIN`. Заголовки `Host` и `X-Forwarded-*`
не используются для выбора доверенного адреса. При отсутствующем или некорректном
`APP_ORIGIN` в production POST возвращает `APP_NOT_CONFIGURED`.

## Каталог

[endpoints.ts](../src/shared/api/endpoints.ts) объединяет URL, HTTP-методы и
контракты операций. `apiClient` определяет типы ответа и параметров по переданному
эндпоинту. Каталог `API_ENDPOINT` плоский; операции регистрации, восстановления
пароля, корзины и DaData имеют префиксы `registration`, `recovery`, `basket`, `dadata`.
Модели данных находятся в [types/](../src/shared/api/types).

Транспорт разделён по среде выполнения:

- `browser/` — Axios для браузера.
- `server/` — серверный Axios, конфигурация backend и прокси; правила заголовков
  и cookies общие для обоих серверных способов обращения к API.
- `types/common.ts` — общие модели, `types/endpoint.ts` — типы контрактов,
  `types/request.ts` — типы настроек запросов.
- `errors.ts` — разбор ответов Bitrix, `path.ts` — подстановка параметров пути.

Прокси разрешает только операции из каталога. Отключённые маршруты отмечены
`availability`; причина указана в `note`. Ошибки прокси имеют вид `{ code, message }`.
Примеры использования — в [инструкции по запросам](requests.md).

## Будущая автогенерация

Автогенератор пока не подключён. Генератор из OpenAPI должен создавать тот же
`endpoints.ts` и модели в той же папке `types/`, сохраняя имена операций, моделей
и экспорт `API_ENDPOINT`. Тип разрешённых операций `TRegisteredEndpoint`
выводится из каталога в `types/endpoint.ts`.
Общие типы в `types/common.ts`, `types/endpoint.ts` и `types/request.ts`
поддерживаются отдельно, вспомогательные функции
каталога включаются в шаблон генератора. Клиент и подстановка параметров пути
поддерживаются отдельно от генерируемых файлов.

Сопоставление `operationId` с текущими плоскими ключами и отметки отключённых
маршрутов задаются в конфигурации генератора. Описание OpenAPI должно учитывать
форматы ответов Bitrix, DaData и файлов. При соблюдении этих условий подключение
генератора сохранит структуру и импорты; изменения самого API могут потребовать
исправлений в модулях.
