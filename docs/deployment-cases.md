# Сценарии пайплайна

[К основной документации](../README.md) · [Схема деплоя](deployment.md)

Один workflow `pipeline.yml`, две джобы: **Проверки и сборка образа** (`build`) →
**Деплой на VPS** (`deploy`). Для других веток `build` выполняет только проверки.
Сценарии сборки образа и деплоя ниже относятся к `main`.

## Один push с несколькими коммитами

Запускается один workflow для последнего коммита этого push. Промежуточные коммиты
отдельно не собираются и не разворачиваются.

## Push в другую ветку

Для `feature/*`, `release/*` и любых других веток кроме `main` выполняются `npm ci`,
генерация типов маршрутов и проверки ESLint, Prettier, TypeScript. Production-сборки,
сохранения образа и деплоя нет. Ручной запуск на такой ветке работает так же.

Новый push в ту же ветку отменяет её предыдущие проверки. Push в другую ветку
не прерывает проверки, сборку или деплой `main`. Push тега workflow не запускает.

## Два push, пока идёт build

```text
Push A → build A ── отменён
Push B → build B → deploy B
```

Новый `build` отменяет предыдущий в той же ветке. Отменённая или неуспешная сборка
не допускается к деплою. Проверки входят в `build` и тоже прерываются.

## Новый push во время deploy

```text
Push A → build A → deploy A ────────────► завершение
Push B ──────────► build B → ожидание ──► deploy B
```

Новый push не отменяет работающий Deploy. Проверки и сборка B идут независимо;
к VPS B допускается после освобождения очереди.

## Несколько готовых релизов в очереди

Если A разворачивается, а B и C уже собраны, перед подключением к VPS каждый
ожидавший Deploy проверяет текущий `main`. При `main = C` первая попытка B
пропускается; C разворачивается. После этой проверки уже начатое обновление
не прерывается новым push.

Очередь допускает до 100 ожидающих Deploy. Порядок зависит от момента постановки
джоб в очередь; проверка SHA защищает от установки устаревшего автоматического релиза.
Если сборка C упала, B не становится автоматической заменой C: остаётся работающая
версия. Для явного выбора B нужен ручной Re-run его Deploy.

## Ошибка проверок или сборки

Ошибка ESLint, Prettier или TypeScript блокирует Docker-сборку и Deploy.
Ошибка Docker-сборки или загрузки artifact тоже блокирует Deploy. VPS не затрагивается.
**Re-run failed jobs** повторяет `build` целиком, затем запускает Deploy при успехе.

## Ошибка подготовки или запуска контейнера

- Ошибка Secrets, SSH, скачивания или передачи не заменяет работающий контейнер.
- Ошибка загрузки образа или отсутствие активного `HEALTHCHECK` обнаруживаются
  до остановки старого приложения.
- Ошибка запуска нового контейнера или его healthcheck запускает попытку
  восстановления предыдущего. Джоба остаётся неуспешной, даже если восстановление удалось.
- При первом деплое предыдущей версии нет: восстановить её невозможно.

Результат смотрите в Actions и в `/opt/demetrio/releases/<release_id>/attempt-<N>/deploy.log`.
`deploy.exit` содержит код завершения; `0` означает успех.

## Повторить только неудачный deploy

В нужном запуске нажмите **Re-run failed jobs**, если упал только Deploy,
или повторите отдельно джобу **Деплой на VPS**.

Зависимости и образ не пересобираются: скачивается artifact исходного `build`.
Его `release_id` сохраняется, хотя номер попытки workflow увеличился. Файлы и логи
нового Deploy размещаются отдельно в `attempt-<N>`: работающая попытка не затрагивается.
Если такой каталог уже существует, передача прерывается без перезаписи его файлов.
Secrets и скрипты берутся актуальные. **Любой ручной Re-run допускает старый коммит**,
даже если `main` уже изменился; выбирайте запуск осознанно.

## Вернуть выбранный прежний коммит

1. Найдите в Actions успешный запуск с нужным SHA.
2. Повторите только джобу **Деплой на VPS**.
3. После получения очереди она скачает прежний образ и выполнит обычную замену
   контейнера с healthcheck и восстановлением при ошибке.

Это работает, пока artifact доступен: сейчас он хранится 7 дней.
Если его уже нет, выберите **Re-run all jobs** этого запуска: GitHub использует
исходный SHA, повторит проверки и пересоберёт образ. Повторы доступны в течение
30 дней после исходного запуска. Для более старого коммита создайте revert в `main`.

Откат использует текущую конфигурацию Secrets. Данные backend не откатываются.
Поиск готового образа на VPS по SHA и восстановление прежней конфигурации пока
не реализованы; сохранённых Docker-образов самих по себе для текущего Re-run недостаточно.

## Ручной запуск текущей версии

**Actions → Проверки, сборка и деплой → Run workflow → main** запускает всю цепочку
для текущего `main`. Отдельные ID прошлых workflow вводить не нужно.

## Ручная отмена или потеря SSH

Автоматическая отмена нового push касается только `build`. При ручной отмене Deploy
или обрыве SSH уже запущенный `run-deploy.sh` продолжает работу на VPS независимо
от ВМ GitHub. Красный или отменённый запуск Actions сам по себе не означает,
что контейнер на VPS не обновился.

Проверьте `deploy.log`, `deploy.exit` нужной попытки и состояние контейнера.
Re-run получает новый каталог `attempt-<N>` и ждёт общей блокировки `deploy.lock`,
если прежний процесс ещё работает. Запуск одного и того же каталога одновременно
блокируется `runner.lock`. Не удаляйте файлы работающей попытки.
